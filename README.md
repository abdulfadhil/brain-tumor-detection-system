# Brain Tumor Detection Using 3D CNN

An academic project developed in April 2025 to explore brain MRI processing, interactive 3D visualization, and experimental brain tumor classification using Python and a 3D Convolutional Neural Network (3D CNN).

The project combines medical-image validation, interactive visualization, and experimental model inference in a local Flask web application.

## About the Project

Working with 3D MRI data involves reading medical-image files, preparing volumetric data, checking input consistency, and presenting the results clearly.

This project brings these tasks together in a web application. Users can upload five NIfTI files for one patient, validate the inputs, explore a 3D visualization, and view experimental model output when a compatible trained model is available.

This is an educational prototype, not a clinically validated medical system.

## The Problem

Working with 3D MRI data involves several steps:

- Checking that the required files are available.
- Reading and preparing volumetric MRI data.
- Checking the compatibility of the images and segmentation mask.
- Exploring the data through 3D visualization.
- Running a compatible deep learning model.
- Presenting the results in a web interface.

## The Solution

The Flask application brings input validation, MRI preprocessing, interactive 3D visualization, and optional experimental CNN inference into one local workflow.

The application also reports measurements calculated from the segmentation mask supplied by the user. The mask is not generated by the CNN.

**Important:** The model output is experimental, is not a calibrated probability of disease, and must not be used as a medical diagnosis.

## Key Features

- **MRI input validation:** Checks required files and image compatibility.
- **Multiple MRI inputs:** Accepts T1, T1ce, T2, FLAIR, and segmentation-mask files.
- **NIfTI upload support:** Supports `.nii` and `.nii.gz` files.
- **3D visualization:** Displays MRI data and the supplied segmentation mask interactively.
- **Optional CNN inference:** Attempts inference when the compatible model is available.
- **Mask measurements:** Reports non-zero mask voxels and an approximate volume based on voxel spacing.
- **Web interface:** Combines upload, visualization, and results in one local application.

## How It Works

1. **Select the input files:** Choose the five NIfTI files belonging to the same patient.
2. **Validate the inputs:** The application checks that the required files are present and compatible.
3. **Prepare the T1 image:** The application normalizes the image, samples 64 slices, and resizes them to 128 × 128 pixels for the expected model input.
4. **Visualize the MRI:** The application creates an interactive 3D visualization.
5. **Attempt experimental inference:** If the model is available and inference succeeds, its output is displayed as experimental information.
6. **Review the report:** The report shows available model output and measurements calculated from the supplied mask.

The supplied segmentation mask is not generated by the CNN. Mask measurements depend on the correctness of the supplied mask and are not validated clinical measurements.

## Required Input Files

Select five files belonging to the same patient:

| File suffix | Purpose |
|---|---|
| `_t1.nii` or `_t1.nii.gz` | T1-weighted MRI |
| `_t1ce.nii` or `_t1ce.nii.gz` | T1 contrast-enhanced MRI |
| `_t2.nii` or `_t2.nii.gz` | T2-weighted MRI |
| `_flair.nii` or `_flair.nii.gz` | FLAIR MRI |
| `_seg.nii` or `_seg.nii.gz` | Supplied segmentation mask |

The application has a combined upload limit of 200 MB per request. The five files must use a consistent patient identifier and must have compatible image dimensions and alignment.

Use only data authorized for processing. Do not publish identifiable patient information or private medical scans without the necessary permission.

## Getting Started

### Prerequisites

- A Python version compatible with the declared dependencies.
- Git, if cloning the repository.
- The dependencies listed in `requirements.txt`.
- Five compatible NIfTI files for testing.
- The compatible trained model, if model inference is required.

The trained model and medical datasets are not included in the public repository.

### 1. Clone the repository

```bash
git clone https://github.com/abdulfadhil/brain-tumor-detection-system.git
cd brain-tumor-detection-system
```

### 2. Create a virtual environment

On Windows, run:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
```

### 3. Install dependencies

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

If installation fails, check the Python and package versions before changing dependencies.

### 4. Configure the model

The application looks for the trained model at:

```text
models/brain_tumor_cnn.h5
```

The model is excluded from the repository because of its size. Obtain the model from an authorized source and place it at this path if inference is needed.

A different model may not be compatible with the expected input shape or preprocessing. See `models/README.md`.

The application can still report supplied-mask measurements when optional CNN inference is unavailable, provided the uploaded inputs pass validation.

### 5. Start the application

```powershell
.\.venv\Scripts\python.exe app.py
```

Open this address in your browser:

http://127.0.0.1:5000

This address serves the application locally. It is not a publicly hosted website.

### 6. Upload MRI files

1. Open the application in your browser.
2. Select the five NIfTI files for one patient using the file picker.
3. Submit the files for validation and processing.
4. Review the visualization and report.

The application does not replace medical review. Successful upload or inference does not establish diagnostic accuracy.

## Testing

Run the automated tests from the repository root:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

These tests cover selected input-validation and visualization behaviours. Passing them does not establish clinical performance or diagnostic accuracy.

- The training and inference preprocessing pipelines require further verification.
- The CNN output is experimental and is not a calibrated probability.
- The supplied mask is used for visualization and measurements; the CNN does not generate it.
- Mask measurements are not validated clinical measurements.
- The application has not been clinically validated.
- The application runs locally unless separately deployed.
